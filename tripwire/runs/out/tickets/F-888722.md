# [Critical] Client-controlled price accepted on POST /api/v3/bookings
**Severity:** Critical (9.4) — base 8.1 (price_tamper); asset criticality 1.2 (+0.5); directly realisable financial loss (+0.8)
**Owner:** booking-svc (#booking-eng)  **Status:** OPEN  **OWASP:** API6:2023 Unrestricted Business Flow  **CWE:** CWE-602


## Business impact
Direct revenue loss / financial integrity break in the booking flow; exploitable by any logged-in agent.

## Proof (oracle: `price_integrity`)
Server quoted 4000.0 but booking was created with total 1.0 after sending total=1

```bash
curl -s -X POST 'http://127.0.0.1:8100/api/v3/bookings' -H 'Authorization: Bearer $A1_AGENT_TOKEN' -H 'Content-Type: application/json' -d '{"quote_id": "<QUOTE_ID>", "traveller_id": "<ID>", "total": 1}'
```
Evidence audit IDs: 839 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Never accept prices from the client: recompute the total server-side from the stored quote and reject mismatches.
