# [High] SSRF via user-supplied URL on POST /api/v3/supplier/webhooks
**Severity:** High (8.7) — base 8.2 (ssrf_oob); asset criticality 1.3 (+0.5)
**Owner:** booking-svc (#booking-eng)  **Status:** OPEN  **OWASP:** API7:2023 SSRF  **CWE:** CWE-918


## Business impact
Server can be steered to attacker-chosen destinations (webhook); internal network/phishing exposure.

## Proof (oracle: `oob_callback`)
Server fetched our out-of-band URL supplied in 'url' (callback token 825c43530b19)

```bash
curl -s -X POST 'http://127.0.0.1:8100/api/v3/supplier/webhooks' -H 'Authorization: Bearer $A1_ADMIN_TOKEN' -H 'Content-Type: application/json' -d '{"url": "http://<OOB-HOST>/<token>"}'
```
Evidence audit IDs: 794 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Validate webhook URLs against an allowlist of partner domains, resolve and block private/link-local ranges, fetch via an egress proxy.

## Retest
Automatic on next deploy of booking-svc
