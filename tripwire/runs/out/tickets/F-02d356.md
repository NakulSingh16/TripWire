# [Medium] Mass assignment of privileged field on PATCH /api/v3/me
**Severity:** Medium (6.5) — base 6.5 (mass_assignment)
**Owner:** identity-svc (#identity-eng)  **Status:** OPEN  **OWASP:** API3:2023 BOPLA  **CWE:** CWE-915


## Business impact
Any agency can read or act on another agency's me data, exposing PII/financial data across tenants.

## Proof (oracle: `state_change`)
PATCH /api/v3/me accepted client field 'credit_limit' (5000 -> 782777); GET read-back confirms persistence

```bash
curl -s -X PATCH 'http://127.0.0.1:8100/api/v3/me' -H 'Authorization: Bearer $A1_SUB_TOKEN' -H 'Content-Type: application/json' -d '{"credit_limit": 782777}'
```
Evidence audit IDs: 929, 933, 934 — replay with `python -m tripwire replay <audit_id>`
Related symptoms merged: mass_assignment

## Suggested fix
Bind request bodies to an explicit allowlist DTO (name, phone); ignore/reject privileged fields like role, credit_limit.
