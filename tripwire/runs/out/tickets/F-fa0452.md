# [High] Cross-agency object read (BOLA) on GET /api/v3/invoices/{id}
**Severity:** High (8.1) — base 6.5 (bola_read); asset criticality 1.3 (+0.5); cross-tenant (+0.7); sequential/enumerable IDs (+0.4)
**Owner:** billing-svc (#billing-eng)  **Status:** OPEN  **OWASP:** API1:2023 BOLA  **CWE:** CWE-639


## Business impact
Any agency can read or act on another agency's invoice data, exposing PII/financial data across tenants.

## Proof (oracle: `differential`)
a2_agent (agency 2) read a1_agent's object 1044 (owner/attacker similarity 1.00, denial-baseline similarity 0.00)

```bash
curl -s -X GET 'http://127.0.0.1:8100/api/v3/invoices/1044' -H 'Authorization: Bearer $A2_AGENT_TOKEN'
```
Evidence audit IDs: 865, 868, 873 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Enforce object ownership in the handler: load the object scoped by the caller's tenant (WHERE id=? AND agency_id=token.agency) and return 404 otherwise. Add an object-level authz middleware and a regression test with two agencies.
