# [High] No step-up auth on sensitive change on PUT /api/v3/agency/bank-account
**Severity:** High (7.3) — base 6.8 (missing_step_up); asset criticality 1.3 (+0.5)
**Owner:** identity-svc (#identity-eng)  **Status:** OPEN  **OWASP:** API2:2023 Broken Authentication  **CWE:** CWE-306


## Business impact
Account or session integrity is broken: an attacker can act as other users or keep access after logout.

## Proof (oracle: `business_rule`)
Sensitive action PUT /api/v3/agency/bank-account succeeded with session token only (no current_password/OTP)

```bash
curl -s -X PUT 'http://127.0.0.1:8100/api/v3/agency/bank-account' -H 'Authorization: Bearer $A1_ADMIN_TOKEN' -H 'Content-Type: application/json' -d '{"bank_account": "<NEW_VALUE>"}'
```
Evidence audit IDs: 859 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Require re-authentication (current password or OTP) for bank/payout changes and notify agency admins out-of-band.

Automatic on next deploy of identity-svc
