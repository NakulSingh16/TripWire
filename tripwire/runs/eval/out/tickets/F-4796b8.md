# [High] Cross-tenant rows in collection on GET /api/v3/bookings/export
**Severity:** High (7.7) — base 6.5 (collection_tenant_leak); asset criticality 1.2 (+0.5); cross-tenant (+0.7)
**Owner:** booking-svc (#booking-eng)  **Status:** OPEN  **OWASP:** API1:2023 BOLA  **CWE:** CWE-639


## Business impact
Any agency can read or act on another agency's export data, exposing PII/financial data across tenants.

## Proof (oracle: `tenant_field`)
a2_agent (agency 2) received 13 rows belonging to other tenants (only counts/ids kept as evidence)

```bash
curl -s -X GET 'http://127.0.0.1:8100/api/v3/bookings/export' -H 'Authorization: Bearer $A2_AGENT_TOKEN'
```
Evidence audit IDs: 931 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Scope the collection query by the caller's tenant from the verified token; never return rows across tenants. If a cross-tenant export is needed, gate it behind a platform role.
