# [High] Tenant switch via request header on GET /api/v3/agency/profile
**Severity:** High (8.7) — base 7.5 (tenant_header_switch); asset criticality 1.3 (+0.5); cross-tenant (+0.7)
**Owner:** identity-svc (#identity-eng)  **Status:** OPEN  **OWASP:** API1:2023 BOLA  **CWE:** CWE-639


## Business impact
Any agency can read or act on another agency's profile data, exposing PII/financial data across tenants.

## Proof (oracle: `differential`)
Setting X-Agency-Id: 1 as a2_agent returns agency 1's data (identical to the owner's view)

```bash
curl -s -X GET 'http://127.0.0.1:8100/api/v3/agency/profile' -H 'Authorization: Bearer $A2_AGENT_TOKEN' -H 'X-Agency-Id: 1'
```
Evidence audit IDs: 838, 844 — replay with `python -m tripwire replay <audit_id>`


## Suggested fix
Ignore tenant-selector headers from clients; derive tenant only from the verified token (or validate membership before honouring the header).
